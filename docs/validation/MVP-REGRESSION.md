## Regression scenario and decision

The real local backend regression creates separate patient/therapist accounts, accepts an invitation, publishes and edits a prescription, uploads a completed result pinned to its original version, replays a lost acknowledgement, verifies one parent/child result, reads detailed therapist history, rejects cross-account reads and revoked access, and records consent/privacy requests. Instrumented Room/worker tests exercise offline errors and close/reopen with the exact stored payload. These complementary checks are not presented as one physically executed patient session. The admin regression adds server-enforced staff/status/link/catalogue controls and old-JWT denial.

Executed counts and individual test names are in sprint-04-implementation-test-results.json and the backend/auth/resource reports. Build, lint, module boundaries, migration replay and native packaging checks are linked from SPRINT-04-IMPLEMENTATION.md. An earlier administrator retry error was found and fixed before final acceptance. No currently observed failing engineering test is deferred as a therapist/device check.

**Engineering decision: GO for continued development and synthetic MVP demonstration. Clinical/production release: NO-GO pending S5 evidence and owner-operated release preparation.** Deferred phone/therapist/representative reviews remain unchecked in POST-IMPLEMENTATION-CHECKLIST.md. API-36 target upgrade, native page compatibility, model terms, hosted email, signing, approved policies, restore drill and account/store requirements are tracked in PRODUCTION-READINESS.md. No store approval, clinical sign-off or physical accuracy result is claimed.
