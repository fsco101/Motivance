## Administrator workflow

The native Administrator portal and Administration workspace support account enable/disable, trusted staff grants/revocations, therapist/patient links, exercise activation and bilingual instruction publication. Changes require confirmation. An active server-controlled admin role is checked on every administrative RPC. Signup metadata and the role selector cannot grant it. Initial provisioning remains a trusted operator action; no privileged key enters the APK. Self-role/status changes are rejected, serialized account/role/link mutations prevent two admins concurrently removing each other's authority, and a removed therapist loses its links/assignments/invitations. Existing JWTs observe server-side changes. Relinking does not revive old prescriptions.

Catalogue edits append an exercise version of the existing supported algorithm, including English and Filipino instructions. Historical exercise and prescription rows remain immutable. Deactivation blocks new prescriptions, while earlier references remain intact. Account lists use 50-row keyset pages; links/catalogue display at most 500/100 records with the bound disclosed. Larger inventories need expanded pagination.

`scripts/test_administration.py` exercises real local GoTrue/PostgREST with disposable fixtures, including every RPC denied to anonymous/patient/therapist callers, direct-write denial, role changes, old-token disable/revocation, link recovery, catalogue history and audit events. It cleans only its own users/catalogue. See sprint-04-admin-backend-results.json. ViewModel tests cover late-response isolation, failed-read clearing/retry, pagination and duplicate-click suppression. The emulator checks confirmation/cancel and directory refresh after a change. An initial retry-state defect was caught and fixed: a successful retry now clears the previous failure flag.

## Lifecycle and sustained-state hardening

The camera is active only while the Activity is RESUMED. Each stream owns its executor/detector and a disposal guard. At most one inference result awaits main-thread delivery, preventing a slow UI from retaining an unbounded bitmap/result queue. Disposed/backgrounded/paused callbacks cannot feed assessment; a result over one second old interrupts rather than updating measurements. Rotation source bitmaps are released when separate from the displayed upright bitmap. Raw frames remain memory-only.

The native API35 emulator camera/model smoke test verifies inference before and after background/rebind and no recording without explicit Start/consent. The initial host-webcam stream supplied no frames; a cold boot with command-line emulated front/back cameras passed. This changes only the test input, not the saved AVD configuration. A lifecycle revision invalidates a delayed Start after interruption, including while Room is writing consent. The instrumented regression holds a database transaction, requests Start, interrupts, then releases the write; no session starts or ID is fabricated. Existing file-backed Room/sync tests verify completed payload persistence through close/reopen, owner isolation, schema upgrades and lost acknowledgement retry. Synthetic repeated cycles retain exactly 1,600 repetitions across interruptions; a 54,000-frame diagnostics trace remains capped at 300 samples. These are simulated duration/state checks, not a phone soak test or proof of leak-free native camera behavior.

Severe thermal status (Android status >=3) pauses measurement and disposes camera resources; the user can cool the phone and resume with fresh calibration. Missing thermal telemetry never rejects a phone. After at least 60 samples, p95 processing over the existing provisional 250ms target shows an advisory. This does not certify hardware eligibility or clinical accuracy. Physical 15-minute heat/battery/memory and reference measurements remain deferred, with actual maximum duration and supported phones to be confirmed.
