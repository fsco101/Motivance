# Database implementation decisions

The authoritative entity relationships are in `docs/PLAN.md`; the executable schema is `supabase/migrations/202610310001_foundation.sql`. Fresh startup and reset have executed the migration and synthetic seed successfully. All 18 pgTAP access/integrity tests pass; `docs/validation/database-test-results.log` records the result. The live auth check also verifies signup provisioning and patient isolation through the API.

## Access matrix

Anonymous clients have no patient-table privileges. Active patients read their own profiles, role records, assignments, prescriptions, sessions and measurements; they cannot grant roles or alter prescriptions. Patients may append their own session results, measurements and consent events subject to ownership constraints. Assigned active therapists can read the linked patient's records and append prescriptions for an active assignment. Revoking a link removes that access. Administrators can review permitted records but role/link mutations remain trusted backend operations. Child measurements inherit access through their session. Account activation and role membership cannot be edited by patient clients.

Sessions have client-generated UUIDs and a composite foreign key binding the prescription version to the same patient. The schema rejects negative counts and reversed/nonfinite ranges and end times preceding start times. Exercise/prescription versions and historical results/events reject in-place mutations. Atomic ingestion and conflict handling are Sprint 3 work; direct table inserts are not advertised as a completed synchronization protocol.

Indexes cover active therapist-patient lookups, active patient assignments, patient session timestamps and consent history; measurement primary keys cover parent-session lookup. Published exercise versions are immutable. A draft catalogue entry remains inactive/unpublished until therapist approval; publishing must append an approved version.

## Retention decision for this milestone

S2 adds app-private `motivance-sessions.db` using Room 2.8.5. `cached_prescriptions` stores only supported active assignments for the authenticated patient, their immutable prescription/exercise version, instructions, rules and 24-hour expiry. Cache refresh replaces an owner's cache transactionally; failed downloads preserve the last cache, and expired versions cannot start or resume a session. Offline revocations cannot be detected immediately. Release pilot policy must approve or shorten this freshness window.

`local_sessions` stores UUID, owner, pinned rules, aggregate ROM/counts/duration/quality totals, incomplete reason counts, UTC start/update/end and status. There are no stored camera images, videos or frame-by-frame poses. `sync_outbox` uses the same UUID as primary key and foreign key; completion and insertion commit together. Repeating a completed save returns the existing result. Conflicting ownership or changing a draft's prescription/start time is rejected. Demonstrations remain `LOCAL_ONLY`; prescribed sessions are `PENDING` for S3 ingestion. Upload acknowledgement, retry metadata, server reconciliation and progress aggregation are not implemented in S2.

All application reads filter by current owner. Sign-out deletes that owner's prescription cache and interrupts drafts; aggregate sessions/outbox remain under that owner so unsynchronized results are not silently lost. A different account sees none of them. Guest history is a separate development-only owner. The app disables backup and device transfer for its data. Room is not encrypted; approved local retention/deletion and encryption decisions remain pilot prerequisites. Authentication tokens are memory-only, so clinical offline continuation works only while an authenticated process remains alive; after restart, online sign-in is required before accessing that account's records.

Schema v1 is exported at `android/app/schemas/com.motivance.data.local.SessionDatabase/1.json`. S1 had no local database to migrate. No destructive fallback is configured; any future version must supply and test a migration. Android instrumented tests exercise file-backed reopen/recovery, atomic rollback on injected outbox failure, duplicate completion, account isolation, cache persistence/logout and immutable session configuration.

The local stack is for synthetic development data only. Integration checks remove the synthetic account records they create; the database reset command is confined to the disposable Motivance project. No production patient-data collection or retention period is enabled by this milestone. Records are not automatically cascade-deleted or silently expired. The owner must approve clinical retention, withdrawal/export handling and backup implications before the pilot. Implement a reviewed, audited purge procedure in that phase; do not bypass immutable-history controls ad hoc. This is a documented delivery boundary, not a claim of compliance with an unspecified clinical retention policy.
